# OctoAcme Project Management Documentation

## Welcome to OctoAcme Project Management

This is the central hub for OctoAcme's project management processes and guidance. Whether you're starting a new project, planning execution, or closing out a milestone, you'll find the guidance and templates you need here.

## OctoAcme Project Management Overview

OctoAcme runs all cross-functional projects with a consistent, customer-first approach that emphasizes:

- **Customer-first**: Prioritize customer value and usability in all decisions
- **Iterative delivery**: Deliver small, testable increments rather than monolithic releases
- **Clear ownership**: Each project has named Project Manager (PM) and Product Manager (PdM) roles
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback, learning, and blameless post-mortems

### Core Roles

- **Project Manager (PM)**: Coordinates delivery, schedules, risks, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes backlog, and measures success
- **Developers**: Implement features, collaborate on design and testability
- **QA/Testing**: Validate quality and acceptance criteria
- **Stakeholders**: Provide inputs, feedback, and approvals

### Project Lifecycle

OctoAcme projects follow a consistent lifecycle:

1. **Initiation**: Define problem statement, identify stakeholders, and create high-level timeline
2. **Planning**: Break work into shippable increments, estimate scope, and plan dependencies
3. **Execution**: Build, test, review, and iterate based on feedback
4. **Release**: Deploy to production, verify functionality, and announce to stakeholders
5. **Close & Retrospective**: Capture learnings and feed improvements back into processes

## Project Lifecycle Guides

### 1. [Project Initiation](./octoacme-project-initiation.md)

Start here for new project ideas. Learn how to validate business need, align stakeholders, and create a lightweight plan.

**When to use:** You have a new project idea or feature proposal ready to be explored  
**Key deliverable:** Project One-pager with problem statement, goals, success metrics, and stakeholders

### 2. [Project Planning](./octoacme-project-planning.md)

Turn approved initiatives into actionable plans and backlogs for delivery. Includes estimation, dependencies, and release planning.

**When to use:** After project approval, ready to break work into sprints  
**Key deliverable:** Prioritized backlog with acceptance criteria, release timeline, and Definition of Done

### 3. [Execution & Tracking](./octoacme-execution-and-tracking.md)

Guidance for managing day-to-day execution, team rhythm, quality standards, and progress tracking.

**When to use:** During active development and delivery  
**Key activities:** Daily standups, weekly syncs, PR reviews, quality assurance, metrics tracking

### 4. [Risk Management & Communication](./octoacme-risks-and-communication.md)

Learn how to identify, assess, and mitigate risks. Includes communication templates and escalation paths.

**When to use:** Throughout the project lifecycle to manage risks and keep stakeholders informed  
**Key tools:** Risk register, communication templates, escalation paths

### 5. [Release & Deployment](./octoacme-release-and-deployment.md)

Standardize how OctoAcme releases features to production with checklists, rollback plans, and release notes templates.

**When to use:** When preparing to deploy features to production  
**Key deliverables:** Release notes, deployment checklist, rollback plan, smoke tests

### 6. [Retrospective & Continuous Improvement](./octoacme-retrospective-and-continuous-improvement.md)

Capture learnings and convert them into actionable improvements after sprints, releases, or incidents.

**When to use:** After each sprint, release, or important milestone  
**Key outcome:** Action items with owners and timelines for process improvements

## Key Artifacts Across the Lifecycle

- **Project Charter / One-pager** — Created during initiation; updated as needed
- **Backlog and Sprint Plan** — Created during planning; continuously refined
- **Risk Register** — Started during planning; reviewed weekly
- **Definition of Done** — Established during planning; shared across team
- **Release Notes** — Created before deployment
- **Retrospective Notes & Action Items** — Created after sprints or releases

---

## Communication Cadence

OctoAcme maintains consistent communication to keep all stakeholders aligned:

- **Daily**: Team standups (15 min) — progress, blockers, dependencies
- **Weekly**: PM + PdM sync and project delivery team standups
- **Weekly**: Risk register and status updates to stakeholders
- **Monthly**: Stakeholder briefings and updates
- **Ad-hoc**: Escalations, incident communications, critical decisions
